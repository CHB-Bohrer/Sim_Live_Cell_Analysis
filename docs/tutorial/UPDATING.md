# Updating the tutorial

One command does the routine work. Run it from the repository folder (Windows prompt or PowerShell):

```
scripts\tutorial\update.cmd            what is out of date, and a check of every sentence   (changes nothing)
scripts\tutorial\update.cmd all        bring everything up to date
```

`all` = re-take the screenshots that are stale, record the voice of the sentences whose text changed, rewrite `NUMBERS.md`,
then open all 250 sentences in the player and report script errors and missing pictures / rectangles. About 10 minutes if every
screenshot is re-taken, a minute or two for a few. It does not use the GPU. Nothing leaves the PC.

## The usual cases

| What changed | What to do |
|---|---|
| A dashboard page looks different, or a run / sweep was re-analysed | `update.cmd all` (the status says which pictures are stale and why) |
| You want to change what the voice says | edit the sentence in `scenes_a.js` / `scenes_b.js`, then `update.cmd all` |
| Results or defaults changed | read `NUMBERS.md` (every sentence that states a number) against the dashboard, edit, then `update.cmd all` |
| A control was renamed or a section added | the check prints `no rect <name>`: fix the name in `capture_shots.py` (what to look for on the page) or in the scene, then `update.cmd capture <shot>` |
| A new page or picture | add the capture to `capture_shots.py`, a row to `shot_table.py`, a scene to `scenes_*.js`, then `update.cmd capture <shot>` |
| One picture only | `update.cmd capture pg_cells` (names: first column of `update.cmd` status) |
| Everything from scratch | `update.cmd all --all` |

## How it knows a picture is stale
After each capture, `shots_stamp.json` records for every picture: when it was taken, a hash of the dashboard source files that draw
that page (listed in `scripts/tutorial/shot_table.py`), and the newest result file of the run and sweeps it shows. A picture is
stale when one of those has changed since. `app/dashboard.py` draws several pages, so editing it marks all of them; that is deliberate
(better one capture too many than a wrong picture).

## The parts
| File | What it is |
|---|---|
| `scenes_a.js`, `scenes_b.js` | the narration, one sentence per line, with the picture cue next to it. This is what you edit. |
| `anims.js` | the animated explanations (canvas drawings) |
| `engine.js` | the player (do not need to touch it for content changes) |
| `img/`, `shots_data.js` | screenshots and the position of every control on them: GENERATED by the capture, do not edit by hand |
| `shots_stamp.json` | what each screenshot was made from: GENERATED |
| `NUMBERS.md` | every sentence that states a number: GENERATED, for review |
| `audio/` | recorded voice clips (not in git): GENERATED by `update.cmd voice` |
| `scripts/tutorial/capture_shots.py` | how each screenshot is taken (which run, which page, which controls get a named rectangle) |
| `scripts/tutorial/shot_table.py` | one row per screenshot: capture key, run, source files, sweeps |
| `scripts/tutorial/build_data.py` | copies a capture into `img/`; holds the few hand-set rectangles (`OVERRIDES`) |

## What it needs (already set up on this PC)
- a Python with `playwright` at `%USERPROFILE%\shotenv_tmp\v` (or point `TUTORIAL_PY` at another one); it drives the installed Edge;
- for the recorded voice, the Kokoro environment at `%USERPROFILE%\kokoro_tmp` (set-up in the header of
  `scripts/tutorial/video/make_clips_kokoro.py`). Without it the step is skipped and the browser voice reads edited sentences;
- the showcase runs named in `shot_table.py` under `%SIMLIVE_DATA%\runs`.
The capture starts its own dashboard on port 8502 and stops it again; a dashboard you have open on 8501 is not touched.

## Not automatic
- The MP4 on the Releases page: re-recording takes about an hour and publishing is a decision (see README.md here, "The MP4").
- Whether a sentence is still TRUE. The check finds broken pictures and scripts, not outdated statements: that is what `NUMBERS.md` is for.
- Hand-set rectangles in `build_data.py` `OVERRIDES` can go out of place when a page gains a section above them: look at those scenes after a capture.
